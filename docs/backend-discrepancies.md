# Backend discrepancies

**Historical pinned-source audit.** The authorized hosting follow-up found newer production fixes and supplies the remaining corrections. See [current backend qualification](current-backend.md) for current source branches, actual release scope and verification. Do not apply these six historical patches as a batch over current production.

Audited REST master `59a18b9df641779911b5e8febfe046730703fe92`, CalDAV main `94a1fa41058c790a3240a61c336e466d4716e057` and Auth main `ea76e6ea70dda3f28e278bba40da6e1cb82c453b`. Findings below are source-confirmed; no live account or database was used. The neighboring source checkouts and Matters API were not modified.

| Finding                                    | Source evidence and effect                                                                                                                                                                                                                                                    | Studio handling / review patch                                                                                                                                                                                                                                                                                                                                                                       |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Missing people getter                      | `routes/api/v1/person/controller.js` exports get through `service.get`; person/service.js exports only internalCalendars, createOrUpdate and delete. Key lookup and availability therefore throw.                                                                             | Execute actual routes and show failure. [backend-people-get.patch](backend-people-get.patch) restores the owner-scoped getter using existing Person.byKey/available and VIEW.PERSON. VM regression covers key/availability/invalid interval.                                                                                                                                                         |
| Owner substitution                         | Calendar/person/resource/event mutation services accept body.owner without matching req.instance.                                                                                                                                                                             | Reject differing owner in proxy. [backend-owner-guard.patch](backend-owner-guard.patch) supplies an ordinary auth middleware equality guard; privileged lifecycle remains outside it.                                                                                                                                                                                                                |
| UUID references lack uniform owner bounds  | Calendar resolve/resolveAccess loads by UUID without owner; event create/get/invite can resolve global event/calendar identifiers. unshare resolves membership without verifying the calendar partition. UUID query limiters may execute without a resolved owner-scoped key. | Independently verify actual parent calendars and restrict mutations to session-created records. [backend-reference-boundary.patch](backend-reference-boundary.patch) adds minimal route-reference checks for calendar/event services. It is not a complete backend authorization redesign; actor binding, query UUID lists and cross-owner person/resource associations need further backend review. |

Patches are independent, minimal review artifacts. They are **not applied, committed to backend repositories, pushed or deployed**. `npm test` exercises selected original/patched functions in isolated VM contexts; it does not prove a real database migration, full backend authorization or production readiness. Review patch applicability with `git apply --check` in a separate nonproduction backend branch, add upstream integration tests and follow that repository's review/deployment process before applying. No correction touches Matters API.
